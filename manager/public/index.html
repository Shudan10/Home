Nextcloud

Your own cloud for files, photos, calendars and contacts, running on this machine and nobody else's. Video thumbnails and iPhone HEIC previews are already set up for you.

It runs with its own database and cache, and stays off until you switch it on. Nothing else in this stack depends on it.

Access

Nextcloud turns away requests for names it has not been told about. Publishing it on a domain from the Proxy tab adds that name here for you; this is where to add any others, separated by spaces.

Apply

Changes here restart Nextcloud.

Admin password

Generated when Nextcloud was installed. This is the password for the admin user above, and the panel is the only place it is shown.

This changes it inside Nextcloud straight away and remembers the new one here. Anyone already signed in stays signed in.

Updates

Nextcloud is built here from the official nextcloud:stable image with ffmpeg added for video thumbnails. Updating pulls the newest stable image and rebuilds on top of it. Your files and database live on their own volumes, so a rebuild leaves them alone.

Nextcloud upgrades its own database schema on first start after an image change, so give it a minute before signing in. It is worth taking a copy of anything irreplaceable first.

Open it

Jellyfin

Your own media server: point it at folders of films, TV, music and photos and it fetches artwork and descriptions, remembers where you got to, and streams to phones, tablets, browsers, smart TVs, Roku, Fire TV and Kodi.

Free and entirely self-hosted, with no account and nothing phoning home. Your media stays where it is on your disk and is only ever mounted read-only, so nothing here can alter or delete it.

Media folders

The folders on this machine that hold your media, as full paths. Each appears inside Jellyfin under /media, named after the folder, and each is mounted read-only.

This is the path as this machine sees it, not as another computer sees it over the network. The panel checks each folder exists before saving, because Docker's own response to a path that is not there is to create an empty one and mount that.

Access

Publishing puts Jellyfin on this machine's address so anything on your network can reach it. Leave it off if you would rather it were only reachable through a domain on the proxy.

Apply

Changes here recreate the Jellyfin container. Your libraries and watch history are kept.

Hardware transcoding

When a device cannot play a file as it is, Jellyfin converts it on the fly. That is expensive on the processor, and a graphics chip does it far better.

This passes /dev/dri through to the container. It has to exist on this machine, so the panel checks before saving. You still have to switch the method on inside Jellyfin, under Dashboard → Playback → Transcoding.

Updates

Jellyfin is the official jellyfin/jellyfin image rather than something built here, so updating means fetching a newer one. Your libraries, accounts and watch history live on their own volume and are kept.

Jellyfin migrates its own database on the first start after an update, so give it a minute before expecting the web page to load.

Proxy and domains Gives your apps a proper web address instead of an IP and a port number, with free HTTPS.
off

It takes ports 80 and 443 on this machine, so it stays off until you ask for it. Leave it off if something else here already uses them. Switch it on to add domains and certificates.

Public addresses

Everything here can have a web address of its own. Set up walks the whole thing: a free DuckDNS name, whatever the service needs switched on, the nginx configuration, and an HTTPS certificate.

The outside has to reach this machine somewhere. By default that means forwarding ports 80 and 443 to it on your router. Nothing outside your network can open these addresses until something does.

If 80 and 443 already belong to something else, forward two other outside ports to this machine instead and set them here. The check below then tests those rather than 80 and 443. Certificates work either way: a DuckDNS name is proved with a DNS record rather than an inbound request, so it needs no open port at all. Addresses then carry the port, as https://yourname.duckdns.org:8443.

Proxy hosts

Every name this machine answers for, and what it forwards each one to. The ones the Overview page set up appear here too — this is the same list, with the details it does not ask about.

AddressForwards toHTTPS

Another machine can sit behind this one. Only one machine on your network can hold port 443, but it does not have to be the machine running the service. Choose Custom host:port and give this proxy the other machine's address on your network, and it will forward that name to it — certificate and all, handled here.

So a second machine running something else needs no proxy, no certificate and no forwarded port of its own. It serves plain http on your network, this machine terminates HTTPS in front of it, and each name goes where it belongs.

Remove everything

Deletes every container, image, volume, network and file this stack created, including this panel. Docker itself is left installed, along with anything else you run on it.

  • Every file, photo and calendar stored in Nextcloud goes with it.
  • Base images shared with your other projects are skipped automatically rather than pulled out from under them.
  • One small helper image (docker:cli) is fetched to do the removing, and is the one thing left behind, because it cannot delete the image it is running from. Clear it with docker rmi docker:cli.
  • There is no undo, and no cancelling once it starts. The log appears on screen and runs until this panel is removed.

Set up a public address

1 Which address?

You have names on this panel already. Use one of those, or make another.

1 Create a free DuckDNS name

DuckDNS gives you a name like myhome.duckdns.org and keeps it pointed at this machine even when your home connection changes address. It is free and needs no card.

  1. Open duckdns.org ↗ and sign in with an account you already have.
  2. Type a name into the domain box and press add domain.
  3. Copy the token shown at the top of that page. It is the password for the name.

One DuckDNS name covers everything beneath it, so you can put a subdomain in front and give each app an address of its own: cloud.myhome for Nextcloud and media.myhome for Jellyfin both reach you with nothing further to set up. That is better than sharing one name on paths, because an app served under a path has to be told it is there, and one at its own name does not.
