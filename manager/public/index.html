Open it

Sign in as the admin user with the password generated when it was installed. Both are on the Settings tab, where you can also change the password.

Nextcloud

Your own cloud for files, photos, calendars and contacts, running on this machine and nobody else's. Video thumbnails and iPhone HEIC previews are already set up for you.

It runs with its own database and cache, and stays off until you switch it on. Nothing else in this stack depends on it.

Access

Nextcloud turns away requests for names it has not been told about. Publishing it on your domain from Tunnel & domains adds that name here for you; this is where to add any others, separated by spaces.

Shared folders

Folders already on this machine, shown inside Nextcloud where they are. Nothing is copied — the same files appear in Nextcloud, in Jellyfin, and on the disk.

The path as this machine sees it. Each appears in Nextcloud named after its last folder. Use this instead of pointing the desktop sync client at a folder on this same machine — syncing would store everything twice on one disk.

Apply

Changes here restart Nextcloud.

Admin password

Generated when Nextcloud was installed. This is the password for the admin user above, and the panel is the only place it is shown.

This changes it inside Nextcloud straight away and remembers the new one here. Anyone already signed in stays signed in.

Back up Nextcloud to a drive

Copies the folders Nextcloud is serving onto a drive plugged into this machine. A copy, not a sync — nothing that happens to the originals is repeated onto the drive, which is the point of having one.

Drive

If your drive is not listed, plug it in and open it once in your file manager, then press Rescan.

Schedule

Checking is cheap — about a second, even across thousands of files — so a short interval costs almost nothing. A check that finds no changes does nothing and says nothing; only a real copy appears in the log. A run that finds the drive unplugged records why and waits for the next one.

Deleted files

Off by default, and worth leaving off. With this on the drive is a mirror, and a mirror of a folder you have just deleted something from is a folder with that thing deleted from it.

Apply

Updates

Nextcloud is built here from the official nextcloud:stable image with ffmpeg added for video thumbnails. Updating pulls the newest stable image and rebuilds on top of it. Your files and database live on their own volumes, so a rebuild leaves them alone.

Checked against Docker Hub when you ask, never on its own.

Nextcloud upgrades its own database schema on first start after an image change, so give it a minute before signing in. It is worth taking a copy of anything irreplaceable first.

Open it

Jellyfin

Your own media server: point it at folders of films, TV, music and photos and it fetches artwork and descriptions, remembers where you got to, and streams to phones, tablets, browsers, smart TVs, Roku, Fire TV and Kodi.

Free and entirely self-hosted, with no account and nothing phoning home. Your media stays where it is on your disk and is only ever mounted read-only, so nothing here can alter or delete it.

Media folders

The folders on this machine that hold your media, as full paths. Each appears inside Jellyfin under /media, named after the folder, and each is mounted read-only.

This is the path as this machine sees it, not as another computer sees it over the network. The panel checks each folder exists before saving, because Docker's own response to a path that is not there is to create an empty one and mount that.

Access

Publishing puts Jellyfin on this machine's address so anything on your network can reach it. Leave it off if you would rather it were only reachable through your domain, under Tunnel & domains.

Apply

Changes here recreate the Jellyfin container. Your libraries and watch history are kept.

Hardware transcoding

When a device cannot play a file as it is, Jellyfin converts it on the fly. That is expensive on the processor, and a graphics chip does it far better.

This passes /dev/dri through to the container. It has to exist on this machine, so the panel checks before saving. You still have to switch the method on inside Jellyfin, under Dashboard → Playback → Transcoding.

Updates

Jellyfin is the official jellyfin/jellyfin image rather than something built here, so updating means fetching a newer one. Your libraries, accounts and watch history live on their own volume and are kept.

Checked against Docker Hub when you ask, never on its own.

Jellyfin migrates its own database on the first start after an update, so give it a minute before expecting the web page to load.

Meal Plan

Keep the meals your family actually eats, plan a week of breakfast, lunch and dinner from them, and get the shopping list that falls out of it. Or press Random week and let it choose.

It has its own family password, set under Settings, which is not the password for this panel. That is deliberate: this panel holds the Docker socket, and the dinner list is the one thing handed out to everybody in the house.

Family password

Everyone who plans meals shares this one. Changing it signs everybody out and restarts Meal Plan, which takes a moment.

Where it listens

Source

Checked against GitHub when you ask, never on its own.

Put your apps on your own domain

Your apps get addresses like meals.yourdomain.com through a Cloudflare Tunnel. A small connector on this machine dials out to Cloudflare and visitors come back in through it, so there are no ports to open on your router and no certificates to look after: Cloudflare serves HTTPS for you. It works even when your internet provider does not give you an address of your own.

What you need

A domain on Cloudflare, and a Cloudflare API token that lets the panel create the tunnel and DNS records.

The token stays on this machine, in the stack's .env, which only this panel can read. It is used to set up the tunnel and the DNS record for each name you publish, and nothing else.

Setup API token

The panel needs a Cloudflare API token to create the tunnel and the DNS record for each name you publish. Making one takes a couple of minutes.

Before you start

Your domain must be on Cloudflare and show as Active. If you bought it somewhere else, add it at dash.cloudflare.com ↗ and change its nameservers to the ones Cloudflare gives you.

Open the form

  1. Go to dash.cloudflare.com/profile/api-tokens ↗.
  2. Select Create Token.
  3. Under Custom token, select Get started.

Do not use the Global API Key further down the same page. It controls your whole Cloudflare account, and the panel cannot use it.

Fill in the form

  1. Token name — any name, for example homelab.
  2. Permissions — add these three rows. The first row is already there; select + Add more for each of the others.
    AccountCloudflare TunnelEdit
    ZoneDNSEdit
    ZoneZoneRead
    Type in the middle box to search. If Cloudflare Tunnel is not listed, choose Cloudflare One Connector: cloudflared.
  3. Account Resources — Include → All accounts, or your own account.
  4. Zone Resources — this section appears after you add the first Zone row. Set it to Include → Specific zone → your domain.
  5. Token expiration — No expiration, or 1 year. When a token expires, apps already published keep working. Adding or removing names needs a new token.
  6. Client IP address filtering — leave it empty. A filter stops the token working if your home internet address changes.

Create and copy

  1. Select Continue to summary. Check that it lists the three permissions above.
  2. Select Create Token.
  3. Copy the token with its copy button. Copy only the token, not the curl command under it. Cloudflare shows the token once.
  4. Open the Tunnel tab, paste the token, and select Connect.

A token is about 40 characters or more, with upper and lower case letters and numbers. If yours contains only 0–9 and a–f, it is the Global API Key or a token ID, not a token.
